# Aurora Location 的蜂窝与代理之路

更新: 2026-09-24. 本文描述项目实验结果, 不把特定设备和系统版本上的观察当作通用平台保证.

## 当前结果

用户已确认 Wi-Fi 和蜂窝下均可修改定位, Aurora VPN 在两种网络下均可用. 用户进一步明确: 本次测试包含 Wi-Fi 建立的定位会话切到蜂窝后保持.

这是用户真机反馈. 工具侧另已验证 Aurora VPN 内部节点传输链, 以及 Location 的真实 DVT 握手. 节点故障恢复、15 分钟锁屏和 clear 后持续传输尚未逐项取证, 不宣称所有稳定性场景完成.

## 我们走过的路

| 阶段 | 做过什么 | 结果与下一步依据 |
| --- | --- | --- |
| Wi-Fi 基线 | Shadowrocket 本机 WireGuard peer + App 中继 + idevice | 完整定位可用, 配对与 DVT 引擎有正常对照 |
| 蜂窝问题 | 比较 TCP、UDP 回送、真实开发者协议 | 普通网络成功不能证明 RPPairing 成功, 纯蜂窝曾在该阶段 EOF |
| IKEv2 实验 | 原生 IKE、端口绕行、旁路、双 VPN | 传输和系统服务准入各有断点, 没有成为最终组合方案 |
| 协议分层 | 为 FFI 添加 TCP/RPPairing/listener/TLS/Adapter/RSD 阶段诊断 | 明确失败层级, 不再从一个外层 EOF 推测所有原因 |
| 本机 VPN 对照 | LocalDevVPN 与自有 LocalTunnel | 短暂关闭蜂窝后真实开发者会话可建, 但没有外网代理 |
| 两步到一键 | 先启动 VPN, 临时关蜂窝, 定位, 恢复蜂窝 | 用户验证后用系统快捷指令串联, 不使用私有蜂窝开关 API |
| 独立 Aurora VPN | 复用 Hako/mihomo 衍生核心, 在收包入口加入本机分流 | 一个 VPN 同时处理代理和开发者通道, Location 保留定位职责 |
| 正式配置验证 | 解决大规则集构建的内存分配问题 | 完整配置加载, 代理与定位组合通过用户双网络及跨网保持测试 |

## 两个关键区别

### 新建会话与保留会话

首次蜂窝建连仍通过短暂断蜂窝流程. 这与 Wi-Fi 建好的会话切到蜂窝继续使用是两个场景. 后者已获用户成功确认, 不需要为了切网而主动断开 VPN 或重新执行助手.

若后续指令失败, App 会停止保持并显示状态未知, 不假装仍在定位. 此时重新走蜂窝修改流程建立会话. 地图停留在旧模拟点本身不能证明会话仍可控制.

### 结束定位与结束 VPN

原 LocalTunnel 是 Location 自己管理的本机通道. 新外部模式中 VPN 属于 Aurora VPN, 其生命周期不随 Location clear、取消或失败结束. URL 回调只协调连接, 节点配置与凭据不经回调传递.

## 经验

1. 分层取证. TCP connected、VPN 图标、回送计数、DVT 成功和地图实际效果各自证明不同事情.
2. 先对照后修复. 系统日志中的接口排除参数和自有 listener 对照支持路径准入方向, 不代表已解释全部系统内部行为.
3. 保留成熟部分. 复用配对、定点和步行引擎; 代理采用成熟核心, 不重写客户端配置生态.
4. 失败要可恢复. 单次令牌、期限、阶段检查和持久化网络恢复标记不可省略. App 重启不自动重放位置指令.
5. 用真实配置. 临时单节点不能覆盖大规则下载/解析的内存峰值, 需要分配证据才能作最小优化.
6. 验收隔离环境影响. 测试 Wi-Fi 自带透明代理, 必须核对 App 内部代理链与字节数; 镜像和 USB 条件也应记录.
7. 尊重证据边界. 用户成功反馈、自动回归与工具实测分别记录, 不把未测的恢复和锁屏场景补成成功.

## 代码与复现入口

- `Core/AuroraVPN.swift`: 严格的外部 VPN 请求/回调解析.
- `Core/CellularShortcut.swift`: 蜂窝助手阶段与一次性令牌.
- `App/AppState.swift`: 通道选择、恢复流程与定位会话生命周期.
- `LocalTunnel/PacketTunnelProvider.swift`: 原通道的本机反射实现.
- `Vendor/idevice/SOURCE.md`: 固定 FFI 版本、补丁与构建说明.
- [测试计划](TEST_PLAN.md): 自动检查和真机边界.
- [早期分层实验材料](CELLULAR_REVIEW_BRIEF.md): 2026-09-17 历史证据, 当时的候选限制不能覆盖后续已授权的新实现.
- [Aurora VPN 完整技术历程](https://github.com/AuroraNest/Aurora-VPN/blob/Aurora/initial-vpn/docs/JOURNEY.md): 收包分流、规则内存修复和 SDK 可复现构建. 该仓库访问受其权限控制.

运行 `sh scripts/check.sh` 检查协议解析、会话生命周期和原功能回归. 此命令不替代设备上的定位验收.
